Every tool must have a `name` that follows the naming convention configured by the organization, `snake_case` by default. The name is the identifier clients use to call the tool, so a single convention across all tools makes them predictable.

The rule checks the `name` of every tool in the root `tools` array. A tool that is not an object, has no `name`, has a `name` that is not a non-empty string, or has a `name` that does not follow the convention is a violation.

Only `tools[*].name` is checked: titles, `_meta` and the contents of `inputSchema` and `outputSchema` are ignored. `$ref` is not resolved, and the length of the name is not checked.

Parameters
----------

- `naming-convention` — naming convention every tool name must follow: `snake_case` (default), `camelCase`, `kebab-case` or `UpperCamelCase`. Letter case, spaces, hyphens, underscores and a trailing `case` are ignored, so `snake`, `camel`, `kebab` or `upper camel` also work, and `PascalCase` and `lowerCamelCase` are read as `UpperCamelCase` and `camelCase`. Any other value falls back to `snake_case`.

| Convention | Compliant names | Noncompliant names |
|---|---|---|
| `snake_case` | `create_issue`, `get_file_contents_v2`, `verify_2fa`, `search` | `createIssue`, `create-issue`, `Create_Issue`, `CREATE_ISSUE`, `create__issue`, `_create_issue`, `create_issue_`, `2fa_verify` |
| `camelCase` | `createIssue`, `getFileContentsV2`, `getHTTPStatus`, `search` | `CreateIssue`, `create_issue`, `create-issue`, `2faVerify` |
| `kebab-case` | `create-issue`, `get-file-contents-v2`, `verify-2fa`, `search` | `createIssue`, `create_issue`, `create--issue`, `-create-issue`, `create-issue-` |
| `UpperCamelCase` | `CreateIssue`, `GetFileContentsV2`, `HTTPStatus` | `createIssue`, `create_issue`, `Create_Issue`, `search` |

Every convention starts with a letter and allows only ASCII letters and digits besides its own separator, used once between words: dots (`admin.tools.list`), spaces, colons, slashes, `$`, accented letters, emoji and leading, trailing or doubled separators follow none. camelCase and UpperCamelCase allow consecutive capitals, so acronyms such as `getHTTPStatus` and `HTTPStatus` pass. A one-word lowercase name such as `search` follows snake_case, camelCase and kebab-case.

Configuration Example:
---------------------------------

In apiquality, choose the convention in the `naming-convention` parameter of the rule in the MCP style guide.

With the Spectral CLI, keep a copy of this repository and redefine the rule in your own ruleset, declaring the functions folder of the copy:

```yaml
extends:
  - ./mcps-style-guide/mcp-ruleset.yaml
functionsDir: ./mcps-style-guide/functions
functions:
  - mcp-tool-naming-convention
rules:
  mcp:MCR001:
    description: "Every tool must have a name that follows the configured naming convention (default: snake_case)."
    message: "MCR001: {{error}}"
    severity: error
    resolved: false
    given: "$"
    then:
      function: mcp-tool-naming-convention
      functionOptions:
        naming-convention: camelCase
```

Noncompliant Code Example
-------------------------

```json
{
  "tools": [
    {
      "name": "create_issue",
      "description": "Creates an issue in a project.",
      "inputSchema": { "type": "object", "properties": { "summary": { "type": "string" } } }
    },
    {
      "name": "listPullRequests", // Noncompliant {{MCR001: Tool name 'listPullRequests' must be snake_case.}}
      "description": "Lists the pull requests of a repository.",
      "inputSchema": { "type": "object" }
    },
    {
      "name": "search-code", // Noncompliant {{MCR001: Tool name 'search-code' must be snake_case.}}
      "title": "Search code",
      "description": "Searches code across repositories.",
      "inputSchema": { "type": "object" }
    },
    { // Noncompliant {{MCR001: Tool must have a snake_case name.}}
      "title": "Get user",
      "description": "Returns a user.",
      "inputSchema": { "type": "object" }
    },
    {
      "name": null, // Noncompliant {{MCR001: Tool name must be a non-empty snake_case string.}}
      "description": "Lists the boards.",
      "inputSchema": { "type": "object" }
    }
  ]
}
```

Compliant Solution
------------------

```json
{
  "tools": [
    {
      "name": "create_issue",
      "description": "Creates an issue in a project.",
      "inputSchema": {
        "type": "object",
        "properties": { "name": { "type": "string", "description": "Issue name, e.g. \"Login-Bug\"." } }
      }
    },
    {
      "name": "list_pull_requests",
      "description": "Lists the pull requests of a repository.",
      "inputSchema": { "type": "object" }
    },
    {
      "name": "search_code",
      "title": "Search code",
      "description": "Searches code across repositories.",
      "inputSchema": { "type": "object" }
    },
    {
      "name": "get_user",
      "title": "Get user",
      "description": "Returns a user.",
      "inputSchema": { "type": "object" }
    }
  ]
}
```
